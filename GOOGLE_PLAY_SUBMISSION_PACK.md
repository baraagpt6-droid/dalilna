These answers reflect the source/configuration and the existing privacy/Data Safety worksheet. Review the final signed AAB and live SDK configuration before submitting.

The current policy states that Dalilna is not designed for children. Select **18 and over only** if the developer confirms that the intended audience is adults. ### Data Safety — working answers

- Does the app collect or share user data? **Yes**.
- Is any data shared with third parties? **Yes**. Google Mobile Ads receives SDK data; the optional cloud assistant and search/geocoding providers may receive the inputs required for the feature. Disclose provider roles accurately.
- Is data encrypted in transit? **Yes, subject to final endpoint and speech-provider audit**. App APIs use HTTPS; confirm all runtime endpoints and the speech-recognition provider before submission.
- Can users request deletion of their data? **Yes only after** the public support/privacy mailbox is active and the request process is monitored. There is no central customer/merchant account to delete; local profile/favourites are removed by clearing app data or uninstalling. Shared server listings require a request to the operator and moderation.
- Does the app create accounts? **No central customer or merchant accounts**. Profile selection and preferences are local. An admin interface exists separately.
